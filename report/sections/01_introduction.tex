\section{Introduction}
\label{sec:intro}

High-performance computing (HPC) clusters run many jobs at once, and a scheduler decides which job runs on which compute node.
A poor placement leaves one node overloaded while another sits idle.
Placement must also respect interactions between jobs: two memory-bound jobs on the same node slow each other down, so schedulers let users declare \emph{anti-affinity} rules that keep such jobs apart.
Even splitting $n$ jobs between two nodes has $2^n$ possible placements and is NP-hard in general.

The Quantum Approximate Optimization Algorithm (QAOA)~\cite{farhi2014} is a leading candidate for such problems on near-term quantum devices~\cite{preskill2018}.
It rewrites the problem as an Ising Hamiltonian whose lowest-energy state is the best solution~\cite{lucas2014}, prepares a low-energy state with a short parameterised circuit, and tunes the circuit's parameters with a classical optimiser.
Large enough quantum hardware is not available to us, so we simulate QAOA.
Simulation is itself an HPC problem: $n$ qubits need $2^n$ complex amplitudes, so each extra qubit doubles the memory and the work.
We use GPUs through NVIDIA's CUDA-Q platform~\cite{cudaq}, so HPC appears twice: as the application we schedule for, and as the tool that makes the study possible.

We place $n$ jobs on two nodes so that the workloads are as balanced as possible while conflicting jobs stay apart (Fig.~\ref{fig:pipeline}), and ask four questions.

\begin{enumerate}
  \item[\textbf{RQ1}] \textbf{Quality.} How close does QAOA get to the optimal schedule, and does it improve with circuit depth?
  \item[\textbf{RQ2}] \textbf{Classical comparison.} How does QAOA compare with simulated annealing, an exact solver and standard partitioning heuristics?
  \item[\textbf{RQ3}] \textbf{Noise.} How much do hardware errors degrade QAOA?
  \item[\textbf{RQ4}] \textbf{HPC scalability.} How much faster are GPUs than CPUs at simulating these circuits, and how large a problem can we reach?
\end{enumerate}

We do not aim to show a quantum advantage: at sizes that can be simulated, classical methods win easily, and we show this directly.
Instead we aim for a correct formulation, a reproducible implementation and an honest analysis of where QAOA works and where it struggles.

Section~\ref{sec:conclusion} summarises our answers to the four questions.
